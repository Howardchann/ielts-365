一、周磁贴按压反馈不一致（bug）

代码事实：所有周磁贴是同一个模板（weeks.wxml:42，hover-class="hover-dim"），按压样式 .hover-dim{opacity:.55; transform:scale(.96)}。准备期各磁贴数据完全一致（无「本周/已过」差异标记），不存在模板或数据层面的差异——所以「部分磁贴按下去整卡变暗、部分没反应」不是我们的逻辑写错了，指向微信 WebView 的已知不稳定：opacity / transform 属于合成器属性，页面 hide→show（切 tab）后部分节点图层不重绘，hover 态就不上屏；哪些磁贴失效取决于哪些节点没被重绘，恰好符合你看到的「随机、部分」。

修复方案：按压反馈改「背景变色」（重绘属性，可靠性最高）

三、喇叭等高对齐：em 方案 vs 统一尺寸，二选一推荐统一尺寸

你的核心洞察完全正确：视差的根源是「图标高度固定」而文本墨水高度在变——只要图标等高且行框居中，视差就收敛。落地有两条路，先直接回答你上一轮的问题：

你问的完全对：em 方案下，同一页面的喇叭会大小不一。喇叭高度跟随所在行字号——单词行（词 32rpx）→ ≈24rpx，例句行（例句 25rpx）→ ≈21rpx，同一页差 3rpx。虽然比现状（32 vs 26，差 6rpx 且方向无理）更收敛，但确实不满足「同页所有喇叭一样大」。所以补了统一尺寸方案：每页所有喇叭取同一个固定值、各自行框居中——同页严格一致，同样消除视差。两案对比：
方案 em · 跟随各自文本（同页 24 / 21 微差）
喇叭与所伴文本严格等高：图标:文本比例恒定，但同页两行喇叭差 3rpx（24 vs 21）。
方案 统一 · 同页所有喇叭同一尺寸（24 / 24）
同一页面全部等大：扫一眼就知道「这些都是播放键」。例句行喇叭比例句墨水高约 3rpx，居中后观感几乎无差。

诚实边界（两案都适用）：CSS 拿不到单个词的字形墨水盒，所以「逐词墨水定位」不可实现；两个方案消除的都是尺寸视差（图标忽大忽小、忽高忽低的主因）。go / it 这类「无升部词」的墨水中点天然偏下，仍会残留约 1px 级观感差——文字排版的物理事实，任何方案都消不掉，但幅度从现在的 2-3px 收敛到 1px 内。
怎么选：要「同页扫过去所有播放键一样大」→ 统一尺寸（推荐，直观一致性最强）；要「喇叭严格匹配每行文本的高度」→ em（同页有 3rpx 微差）。两案都是纯 CSS 改动，SVG 资源零改动，可随时互换。
