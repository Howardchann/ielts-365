## 1. 演进历史（为什么长成现在这样）

```
H5 版（SpeechSynthesis，各设备可用声音乱七八糟、无法选发音人）
  → 小程序 + 微信同声传译插件（个人主体搜不到 + 50 字符上限，作废）
  → 小程序 + 有道在线 TTS（能用，但音库对"整句"覆盖极差，约 89% 例句无声）
  → 小程序 + 百度兜底 + 逐词连播（逐词蹦对零基础是伪解，用户否决）
  → 现在：云厂商 TTS 一次性预生成静态音频 + 云存储托管   ← 当前
```

关键转折点是用户的一句话：

> 「不能换源吗？阿里云腾讯云百度智能云的 api 等……逐词读句子对我这种零基础学习的来说本身就很难受」

**逐词连播对零基础是伪解**：连读、重音、语调、句子节奏全丢，而这四样恰恰是零基础学句子最需要的东西。该方案已作废，只保留给「单个单词」。

## 2. 关键决策（**改动前必读**）

### 2.1 语音：三层链路

```
① 预生成音频（本地缓存）        同一次朗读过的，之后离线可播，零延迟
② 预生成音频（云函数签名链接）  首次播放走云端，播完在后台落本地缓存
③ 在线兜底：有道整句 → 百度整句 预生成缺失/信号极差时用；句子不再逐词连播
```

- 音频源：**edge-tts**（微软 Azure 神经语音同款引擎，无需密钥），音色 **`en-US-AvaMultilingualNeural`**（用户从 6 个音色里试听选定，最接近人声）
- 默认语速 0.90×；**慢速门限 `SLOW_GATE = 0.85`**：`rate ≤ 0.85` 播**慢速音频**（源端 `rate=-30%`，自然放慢、音高不变）并把 `playbackRate` 设为 1；`rate > 0.85` 播正常音频并按 `rate` 变速
- 朗读方式（`engineMode`）：`auto`（预生成优先，失败切在线）/ `pregen`（仅预生成）/ `online`（仅在线），设置页三选
- **口音切换（美/英）只对在线通道生效**——预生成音频恒为美音 Ava。这是事实，别写成"支持英美双音源"；设置页文案已如实说明

**为什么彻底放弃微信同声传译插件**（`wx069ba97219f66d99`）——三条依据仍然成立：

1. **个人主体根本搜不到**（添加路径：mp.weixin.qq.com → 设置 → 第三方设置 → 插件管理）。社区答复："个人不支持，因为这个插件的类目个人主体没有。"
2. **50 字符硬上限**，本项目有 **131 条语法例句超标**（最长 222 字符）→ 读不出来，属结构性残缺。
3. **成本本就不是问题**：全库字符量在云厂商免费额度内（微软 50 万字符/月），一次性生成 35 分钟。真正的成本是「正规云 TTS 都要 SecretKey 签名 → 密钥不能进前端 → 必须搭服务端」，而这个服务端本项目已经有了（云函数）。

> ⚠️ **请不要**因为"官方插件更正规"就改回去。

### 2.2 音频为什么走「云函数签名」而不是 `wx.cloud.downloadFile`

这是本项目最反直觉的一处，**改错了会直接全盘无声**。

**现状**：云开发环境处于免费套餐，云存储权限被**锁定**为「仅创建者和管理员可读写」，且免费期**无法修改**——控制台与后台 API 双双拦截（`ModifyStorageSafeRule 当前套餐无法执行此操作`）。而音频是用**管理端 CLI 批量上传**的，不属于任何用户，安全规则按 `resource.openid` 判定 → 客户端 `downloadFile` / `getTempFileURL` **一律被拒**（实测：无签名直链 403，桶私有，签名必需）。

**解法**：云函数以**管理端身份**运行，拥有全部读写权限，由它批量签发临时链接。

```
客户端 speech.js
  └─ wx.cloud.callFunction({ name:'audio-url', data:{ paths:['w/0/0001.mp3', ...] } })
       └─ 云函数 cloud.getTempFileURL({ fileList:[{fileID, maxAge:7200}] })   // ≤50 条/次
            └─ 返回 { ok:true, items:[{ path, url }] }
  └─ 客户端缓存 URL（TTL 60 分钟）→ wx.createInnerAudioContext().src = url 播放
```

配套约束：

| 项 | 值 / 说明 |
|---|---|
| 云函数源码 | `cloudfunctions/audio-url/index.js`（约 48 行），运行时 Nodejs16.13 |
| 部署 | `tcb fn deploy audio-url --force` |
| 单批上限 | `MAX_BATCH = 50`（`getTempFileURL` 的硬上限） |
| 链接有效期 | `MAX_AGE = 7200` 秒**写死**（各版本文档口径不一，不依赖默认值） |
| 客户端缓存 | `URL_TTL = 60 分钟`（按 2 小时取一半留余量），过期/播放失败即丢弃重签 |
| 签名方式 | **串行队列**（`signQueue`）——并发签名会漏签 |
| 路径白名单 | `/^([ws]\/[0-8]\/\d{4}s?\.mp3\|g\/[0-9]\/[0-9a-f]{8}s?\.mp3)$/`，避免云函数被当成通用签名器 |
| 预热 | `prefetch()` 把当天要用的音频提前签好（分片 ≤50 一批），并顺手落盘前 10 条 |

> ⚠️ **两个容易踩的点**
> 1. **`InnerAudioContext` 播 https 直链不受 downloadFile 合法域名限制**（真机实测，未配域名也能出声）；但**要落本地缓存就必须配 downloadFile 域名**（云存储桶域名 + `dict.youdao.com` + `fanyi.baidu.com`）。落盘失败是静默的，不影响播放。
> 2. 云函数**调用次数**也计入免费配额（20 万次/月）。正常使用每天 3 次左右（120 条音频 ÷ 50），远够。但**别在循环里单条签名**。

### 2.3 音频命名规则（**改命名 = 三处同步，漏一处就静默失效**）

三套音频，两种命名逻辑：

| 套 | 路径 | 命名依据 | 数量 |
|---|---|---|---|
| 单词 | `w/{ai//1000}/{ai}{s?}.mp3` | **词表音频编号 `ai`**（1..8000，＝词频序排名） | 8000 × 2 速 |
| 词汇例句 | `s/{ai//1000}/{ai}{s?}.mp3` | 同上（与单词**共用编号**） | 8000 × 2 速 |
| 语法例句 | `g/{hash%10}/{hash}{s?}.mp3` | **文本 djb2 哈希**（8 位小写 hex） | 765 × 2 速 = 1530 |

- `s` 后缀 = 慢速版。如 `w/0/0001.mp3`（单词正常速）、`w/0/0001s.mp3`（单词慢速）
- 分片目录（`{ai//1000}` → 0..8、`{hash%10}` → 0..9）避免单目录上万文件
- **为什么单词/例句用序号而不用哈希**：8000 词的哈希映射表会膨胀到 **1.2MB+，直接吃掉 2MB 主包**；序号命名让运行时靠 `ai` 字段直接拼路径，**零映射表**
- **为什么语法例句只能用哈希**：语法例句在数据里是纯字符串数组（`day.g.ex[]`），**没有编号字段**，且不想改 `data-p*.js`（那是逐字节迁移来的教学内容）。哈希 = 数据文件零改动

> ⚠️ **djb2 哈希必须 `>>> 0` 转无符号**（`h*33 + charCodeAt` 之后）。初版用 `& 0xFFFFFFFF` 得到 int32，>2^31 的句子哈希为**负数** → 文件名带负号、分桶 `-1`~`-9`、白名单匹配不上，88 个文件传不上去。
> **`hashName()` 的算法必须在这三处逐字一致**：`utils/speech.js` ↔ `_wordbank/dump_grammar_runtime.js`（全量核对脚本） ↔ 云函数 `PATH_RE` 白名单。改任何一处都要重跑全量差集核对。

### 2.4 课程结构：78 周双轨 + 双坡道

```
78 周 / 546 天 / 390 个学习日 / 8000 词
排法：W1, W2 → R1 → W3, W4 → R2 → …… → W49, W50 → R25 → W51 → R26 → W52
                                              ↑ 第 26 个巩固周刻意插在 W51 与 W52 之间，
                                                保证「考前一周」留在最后一周
```

| 项 | 说明 |
|---|---|
| 巩固周位置 | 周号 3,6,9,…,75,**77**（每 2 周原课程插 1 个巩固周，共 26 个） |
| 双轨词汇 | **1125 个主题核心词**留在原周原位（原 1300 词条去重后）＋ **6875 个词频扩展词**按 COCA 升序追加 |
| 双坡道 | 新课日 14→30 词/天（260 天）；巩固日 11→25 词/天（130 天）；合计恰为 8000 |
| 数据分片 | `data-p1..p6.js`，每片 13 周 |
| 巩固周内容 | 每周一个技能主线（构词法/搭配/回译/影子跟读…），5 天各 1 个技能点，**不引入新语法** |

**为什么这么设计**：原课程教学内容恰好 52 周整（260 个语法点全部唯一 + 52 个周日自检），拉到 78 周后多出的 130 天没有现成内容；且**降低每日词量必须增加"带新词的学习日"**——如果只加复习日，词量并不会降。于是新写 26 个巩固周，且用「核心词留在原位 + 扩展词追加」的双轨法，让周主题/每日标题/语法/练习/自检**一行都不用改**。

> ⚠️ **`ai`（音频编号）＝词频序排名，与课程顺序无关。** 所以课程怎么重排，`ai` 指向的音频文件永远不变——**改课程结构不需要重新生成或重新上传任何音频**（这是 09-21 那次重构能零成本完成的关键）。

### 2.6 进度存储与备份

- **纯本地**：`wx.setStorageSync('ielts-365-store')`。换机 / 卸载微信 / 清缓存 → 全部丢失。所以备份**必须存在**。
- **备份**（设置页「进度备份」）：导出 JSON **文本**（自动复制到剪贴板，可粘贴到「文件传输助手」/备忘录），**合并导入**（推荐，取并集，可用于人工跨机同步）/ **覆盖导入**（换机恢复）。
- **`sanitize()` 把外部数据全当不可信**：`checkedDays` key 须匹配 `/^w\d{1,2}d[1-7]$/`（防 `__proto__` 原型污染）、`starredWords` 缺 `w` 即丢弃、字符串截断（词 60 / 释义 80 / 词性 20 / 例句 300）、`rate` 限 0.5~2、`accent` 限 us/uk、`startDate` 须 `YYYY-MM-DD`。解析失败/App 标识不符/空输入均抛**中文**错误。
- **间隔重复**：`reviewWord(word, remembered)`——答对 `level+1`、间隔取 `[1,2,4,7,14,30,60,120]`；答错 `level=0`、`nextReviewAt=now`（立即可复习）。`reviewStats` 随本地数据保存并进入备份。
- **备份合并幂等**：`mergeReviewStats()` 按 `lastReviewedAt` 取较新者，**同一份备份重复导入不会把次数重复累加**（备份是快照，不是增量日志）。

**踩坑备忘**：

- `pip` 必须沙箱外且 `unset *_PROXY`（清华源失败，阿里云镜像可用）
- **ffmpeg / node 不认 Git Bash 风格的 `/d/` 路径**，必须写 `D:/`
- edge-tts 写不了中文文件名（Python 编码），一律用英文名
- 微软服务端**只认 24kHz 家族、码率上限 96kbps**（`audio-24khz-96kbitrate-mono-mp3` 可用；128/160/192、48kHz 系一律 `NoAudioReceived`）
- `tcb login --flow device` 可用；遥测提示会杀进程但凭据已写入
- 环境变量前缀不能写在脚本变量里（会 127），须 `TCB="env NODE_PATH=... node cli"` 这种形式
- `tcb storage upload` 的 cloudPath **不能以 `/` 开头**
- 用 `tcb env list` / `env detail` 查环境实况；**别跑 `env renew` 验证（会真扣费）**

## 8. 平台与主体相关的硬性约束

| 结论 | 依据 |
|---|---|
| 个人主体搜不到同声传译插件 | 用户实测 + 社区答复 |
| **个人主体不能迁移为企业 / 个体工商户** | 微信官方社区："个人主体小程序不支持迁移至任何主体类型……建议注册新的小程序账号"。**换主体 = 重新注册，AppID 会变** |
| 不要用"经营者非本人"的营业执照 | 所有权归经营者，认证与变更全程需对方配合，收款进对方账户 |
| 「教育 > 题库 / 错题解析」类目不对个体户开放 | 提审前在后台类目库实测；本项目实际选用「工具 → 备忘录」（⚠️ 工具类目下**没有「效率」子类目**，旧文档写的「工具 → 效率」是错的） |
| 服务器域名（含 downloadFile）**必须 ICP 备案** | 个人备案需绑国内服务器，另有成本 + 7~20 工作日 → 这是当初选云开发而非自有域名的主因 |

**体验版的实际能力（2026-09 核实，官方文档 + 通行实践）**

| 项 | 结论 |
|---|---|
| 要不要审核 | **不要**。开发者工具「上传」→ 后台「版本管理 → 选为体验版」即可；与正式版**共用**域名 / 类目 / 隐私配置 |
| 有效期 | **无固定过期时间**（对比：不注册账号的「试用版」14 天到期自动注销） |
| 体验成员上限 | 随主体与发布状态递增：**个人主体 15**；未认证未发布的非个人 30；已认证未发布 / 未认证已发布非个人 60；已认证已发布非个人 90 |

| 分享限制（**最容易误判**） | 体验版是**白名单制**：仅 管理员 / 项目成员 / 体验成员 能打开。**非成员扫同一个二维码会提示「无权限访问」**；微信开放社区官方明确「**不支持公开临时权限**」→ 转发二维码放人进来行不通，**必须先把对方加进名单** |

| 想"扫码即用" | 只有一条路：**发布正式版**（~~代价：上线后第 15 天转付费~~ —— 环境已在个人版套餐计费（**免费试用期至 2027-03-22，用户尚未付费**），上线不触发额外转付费；到期续费约 19.9/月） |
