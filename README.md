# ielts-365 · 四实例仓库

> 本仓库自 2026-09-27 起按**同仓 4 目录**划分实例（不再是分支划分）。四个实例同仓同 HEAD，产品功能一致，差异在主题能力：

| 目录 | 实例 | 主题能力 | 说明 |
|---|---|---|---|
| `original/` | 原始不发布版 | 无主题系统 | 取自 main 分支头 `95f1a94` 的快照，留档不开发 |
| `light/` | **主项 / 上线版**（纯浅色） | 定死浅色 | **2026-09-27 起为主项，以后功能开发与上线都在此**；删除色系调整模块，无 darkmode/theme.json |
| `cloud/` | 三色调整完整版 | 跟随系统 / 浅色 / 深色 三态 | 唯一保留色系调整模块的版本；**不再是主项**（深浅模式下闪白/残影未根治，见其文档），仅当主题能力有进展时同步 |
| `dark/` | 纯深色版 | 定死深色 | 删除色系调整模块，无 darkmode/theme.json |

- 每个实例都是**完整的独立小程序项目**（开发者工具以实例目录为项目根打开）；
- 每个实例有**各自的 `AI-CONTEXT.md` 与 `CHANGELOG.md`**，记录该实例自己的问题边界——尤其主题相关问题的适用性在四个实例中不同（如闪白问题家族只在 cloud 实例存在；过渡桥方案当年浅色正常、深色闪白的教训记入 dark 实例文档）；
- cloud 实例的 `AI-CONTEXT.md` / `CHANGELOG.md` 是**完整决策史**的权威来源，light/dark 的文档只写差异与本实例现状。

## 主线开发流程（2026-09-27 起：主项 = light）

1. **功能开发只改 `light/`**——上线、上传体验版也只从 light 出（深浅模式闪白/残影根治前，cloud 不再作为发布形态）；
2. 变更若涉及主题无关的共用逻辑（store/speech/页面结构），需要同步回 `cloud/` 与 `dark/` 并更新其文档，保持四实例功能一致；
3. 上传体验版前在对应实例目录跑 `node tools/stamp-build.js`；
4. CLI 上传：`cli.bat upload --project "D:\idea\ielts-365\light" -v x.y.z -d "..."`。
