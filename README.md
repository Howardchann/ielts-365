# 开溜6.5 · 微信小程序版

> 零基础雅思 **18 个月**学习计划：**4 阶段 / 78 周 / 546 天 / 390 个学习日 / 8000 词**。

| 维度 | 现状 |
|---|---|
| 主体类型 | **个人主体**（决定了下面很多限制） |
| 语音 | **预生成高清音频**托管在微信云存储，由云函数签名分发；在线 TTS（有道 / 百度）仅作兜底 |
| 云端依赖 | 云存储音频（签名分发）+ 云数据库进度同步（云函数 `sync`） |
| 进度 | **本地优先 + 云端同步**：写入先落本机，2.5 秒防抖后与云端合并；设置页可关闭同步，另有 JSON 备份导出 / 导入 |
| 复习 | 内置间隔重复 1/2/4/7/14/30/60/120 天 |

> ⚠️ **本仓库有两条分支，别搞混**
> - **`cloud-sync`（当前分支 · 发布版）** —— 在本地版基础上增加**云数据库多端同步**。依赖云开发付费套餐（个人版，约 19.9 元/月）。
> - **`main`（体验版）** —— 进度**只存本机**，跨机靠「进度备份」导出 / 导入，不产生任何数据库调用，也不依赖付费套餐。
>
> 两个版本共用同一套课程数据与音频，差别只在 `utils/store.js`、`app.js`、设置页与多一个云函数。

> **完整决策背景与「已修复的坑」见 [AI-CONTEXT.md](./AI-CONTEXT.md)；逐次变更记录见 [CHANGELOG.md](./CHANGELOG.md)。**

```

    ├── app.js                   # 云开发 init（音频签名 + 进度同步）
    ├── app.json                 # 页面注册 / tabBar
    ├── app.wxss                 # 全局样式

    │   ├── cloud.js             # 云开发 ENV / FILE_PREFIX / 云函数名
    │   ├── speech.js            # 朗读引擎：预生成音频 → 在线兜底
    │   └── store.js             # 进度：本地存储 + 云端同步 + 间隔重复 + 备份导出导入
    └── pages/

        ├── weeks/               # 78 周总览，点日期直达今日
        ├── review/              # 复习：随机 / 到期 / 重点词
```

## 二、部署步骤

### 1. 注册小程序（免费，个人主体即可）

- https://mp.weixin.qq.com → 立即注册 → 小程序
- 「设置 → 基本设置」查看 **AppID**

### 2. 下载微信开发者工具

- https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html

### 3. 导入项目

- 开发者工具 → 导入项目 → 目录选**含 `project.config.json` 的根目录**
- 本仓库的 `project.config.json` **已填入本项目 AppID**；要部署成自己的小程序，把 `appid` 换成你自己的

### 4. 配置服务器域名（**必须**，漏一个对应功能就废）

登录 mp.weixin.qq.com → 开发管理 → 开发设置 → **服务器域名**，在 **downloadFile 合法域名**里加：

| 域名 | 作用 | 不配的后果 |
|---|---|---|
| `636c-cloud1-d2gfv3f254c476e40-1493393272.tcb.qcloud.la` | 云存储桶（把音频落到本地缓存） | 静默失败：每次朗读都要联网重新拉，**不影响出声** |
| `https://dict.youdao.com` | 在线 TTS 主兜底 | 在线朗读无声（这也是历史上最常见的"坏了"的原因） |
| `https://fanyi.baidu.com` | 在线 TTS 备兜底 | 有道缺字时无备选 |

> 桶域名请以「云开发控制台 → 存储 → 任一文件详情」显示的域名为准（前缀与 `utils/cloud.js` 的 `FILE_PREFIX` 中 `cloud://<环境ID>.` 之后那段一致）。
> ⚠️ 域名填错要等下个月才能改（每月修改次数有限），**一次填对**。

### 5. 开通云开发并部署云函数（**必需**，不是可选）

两件事都靠云函数：

- `audio-url` —— 音频托管在云存储，而**免费期云存储的权限被锁定为「仅创建者和管理员可读写」且无法修改**，客户端云 API 拿不到文件 → 必须靠云函数以管理端身份签发临时链接。
- `sync` —— 进度多端同步。云函数以管理端身份读写数据库、并用 `openid` 识别用户，**客户端不需要任何数据库权限配置，也不用做登录界面**。

- 开发者工具顶部「云开发」→ 开通（若已有环境，把 `utils/cloud.js` 的 `ENV` 和 `cloudbaserc.json` 的 envId 改成你的）
- 部署云函数：

```bash
tcb login                       # 或 tcb login --flow device
tcb fn deploy audio-url -e <你的环境ID>
tcb fn deploy sync -e <你的环境ID>
```

- 建数据库集合：云开发控制台 →「数据库」→ 新建集合 **`progress`**（权限保持默认即可，读写都走云函数）。
  也可以命令行建：`tcb db nosql execute -e <环境ID> --command '[{"TableName":"progress","CommandType":"COMMAND","Command":"{\"create\":\"progress\"}"}]'`
  > 云函数里也做了兜底：集合不存在时会自动创建一次，所以漏建也不会立刻坏。
- 若用命令行上传音频，还需拿到「环境 ID」与「任一文件的完整 fileID」，填进：
  - `miniprogram/utils/cloud.js` 的 `ENV` / `FILE_PREFIX`
  - `cloudfunctions/audio-url/index.js` 的 `FILE_PREFIX`

### 6. 上传音频（**必须分片**，否则会挂死）

规模：**33530 条**（单词 16000 + 词汇例句 16000 + 语法例句 1530），约 **840MB**。

```bash
# 云端路径不能以 / 开头；必须按分片（约 2000 个/片）上传
tcb storage upload <本地目录>/w D:/ielts-audio/w -e <环境ID>
```

> ⚠️ **实测教训**：一次喂 16000 个文件会让并行引擎**挂死 51 分钟且云端 0 文件**（不报错，静默卡住）；改分片后 1 分钟/片，全部约 18 分钟。
> ⚠️ CLI 汇总的 `Failed to upload N` **不可信**（实测报 11 失败实际全在、报 7 失败真缺 7）→ 必须用「云端清单 vs 本地逐文件差集」核对，别信计数。

音频生成/命名/上传的完整脚本清单与踩坑见 [AI-CONTEXT.md](./AI-CONTEXT.md) §6。

### 7. 预览与发布

- 「预览」→ 手机扫码可用全部功能；满意后「上传」→ 提交审核

**只给自己 / 小范围用 → 不用走审核**（推荐路径，本项目当前选择）：开发者工具「上传」→ [mp.weixin.qq.com](https://mp.weixin.qq.com)「管理 → 版本管理」把开发版本**选为体验版** → 「成员管理 → 体验成员」加微信号（个人主体上限 15 人）→ 体验成员扫体验版二维码使用。
体验版搜不到、不能长按识别小程序码、不支持微信支付，但**不触发「发布上线」，免费云环境不受影响**。
⚠️ **体验版是白名单制**：非体验成员扫**同一个二维码**会提示「无权限访问」（微信官方明确「不支持公开临时权限」）。想让谁用，**必须先**把对方的**微信号**加进「成员管理 → 体验成员」（个人主体上限 15 个，可删旧换新）。想做到"扫码即用"，只能发布正式版。
⚠️ 体验版**校验服务器域名**（只有「真机调试」不校验）——第一次上体验版要重点复验音频播放与云函数签名。

以下是**提交审核才需要**的东西：

- 类目建议：「**工具 → 备忘录**」（个人主体可选。⚠️ 工具类目下**没有「效率」子类目**，旧文档写的「工具 → 效率」是错的）
- **必须先完成「小程序备案」**（2023-09-01 起硬性要求，未备案不能提交代码审核）：后台「去备案」→ 平台初审 1–2 个工作日 → **12381 短信须 24 小时内核验**（逾期要从头重交）→ 通管局审核 **1–20 个工作日、不可催**。
  ✅ **备案在审期间不影响体验版**——两件事可以并行，不用干等。⚠️ 审核期间别改小程序名称 / 主体信息
- ⚠️ **提审前必办**：本项目唯一用到的隐私接口是 **`wx.setClipboardData`**（导出备份）。官方把 set/get 同列归入「读取你的剪切板」，**写入也算** → 必须在「提交审核 → 用户隐私保护指引」里声明**剪切板**，否则**正式版**该功能 fail
- ⚠️ `project.config.json` 里的 `urlCheck: false` 只关开发者工具的域名校验；**真机 / 预览 / 体验版永远校验域名**，别拿它当"域名没配也没事"的理由

## 三、进度存储与同步

### 三层结构

| 层 | 位置 | 作用 |
|---|---|---|
| ① 本地存储 | `wx.setStorageSync('ielts-365-store')` | **第一现场**。写入立刻落本地，断网 / 云端故障都不影响学习 |
| ② 云端同步 | 云数据库集合 `progress`（唯一出入口是云函数 `sync`） | 多台设备共用同一份进度。换手机登录同一个微信即自动恢复 |
| ③ 备份导出 | 设置页「进度备份」 | 最后一道保险：云端出事、换微信号、误操作时仍能救回进度 |

### 云端结构：用 openid 认人，没有账号体系

微信会把 `openid` 随云函数调用一起下发，**所以不需要注册、不需要登录界面、也不需要改任何数据库权限**（读写全在云函数里以管理端身份完成）。

| 记录 | `_id` | 内容 |
|---|---|---|
| 核心进度 | `<openid>` | 打卡 / 取消打卡、收藏 / 取消收藏、设置项、`reviewRev` |
| 复习记录分片 | `<openid>#rs0` … `<openid>#rs7` | 单词 → 复习记录，按单词哈希分 8 片 |

> ⚠️ **为什么复习记录一定要分片**：8000 词的复习记录单条约 **800KB**，超过云开发「单条记录 512KB」上限。
> 硬塞进一条记录**不会立刻报错**，而是等用户学几个月、记录攒够了才开始写失败 —— 那种问题极难定位。分 8 片后每片约 100KB。
> 分片号只由云函数计算，客户端完全不需要知道分片的存在。

### 冲突合并规则（多台设备同时用不会丢进度）

真正在用的做法是「**先合并、再写回**」，而不是「谁后写谁覆盖」：

| 数据 | 规则 |
|---|---|
| 打卡 / 取消打卡 | 按天取**更晚的时间戳**。取消过就是真取消，不会被另一台设备上的旧记录复活 |
| 收藏 / 取消收藏 | 按单词取更晚的时间戳 |
| 复习记录 | 按单词取 `lastReviewedAt` **更晚的那一条**（快照语义，重复同步不会把复习次数翻倍） |
| 设置项（开始日期 / 语速 / 口音 / 朗读方式） | 整组按 `settingsAt` 更晚者胜 |

同步时机：本地变更后 **2.5 秒防抖**推云；启动与切回前台（20 秒节流）与云端合并；切后台前把待推的推出去。
**同步失败不影响学习** —— 本地永远是完整的，设置页会显示失败原因，也可以点「立即同步」重试。
数据量大的时候单次只上送 400 个单词（超过就分批，默认 300ms 一批推完）。

### 备份（仍然建议保留）

设置页 → **进度备份**：

| 操作 | 说明 |
|---|---|
| **导出备份** | 生成一段 JSON，自动复制到剪贴板。粘贴到「文件传输助手」或备忘录保存 |
| **合并导入**（推荐） | 保留现有进度，补上备份里缺的部分（打卡取并集、重点词按词去重、复习记录取较新）。手机和电脑各自学完再互导，等于人工同步；**同一份备份重复导入不会重复累加** |
| **覆盖导入** | 以备份为准替换，本机现有进度会被清除（换机恢复场景） |

建议每月导出一次，成本几乎为零。

### 间隔重复

`store.js` 内置 `[1, 2, 4, 7, 14, 30, 60, 120]` 天间隔：答对进入下一档，答错**归零并立即可复习**。复习页有三个页签：**随机 / 到期 / 重点词**。

## 四、语音方案说明

### 三层链路

```
① 预生成音频 · 本地缓存      播过一次后离线可播，零延迟
② 预生成音频 · 云端          云函数签发临时链接 → 播放 → 后台落本地缓存
③ 在线兜底                   有道整句 → 百度整句（句子不再逐词连播）
```

- **音色**：`en-US-AvaMultilingualNeural`（edge-tts，微软神经语音），恒定美音
- **语速** 0.70~1.30×，默认 0.90×；`≤0.85×` 播**慢速音频**（源端 `-30%`，自然放慢、音高不变），`>0.85×` 播正常音频并按倍速播放
- **音源可切换**（设置页）：自动（推荐）/ 仅预生成 / 仅在线 TTS
- **口音切换（美/英）只对在线通道生效**——预生成音频恒为美音。想听英美差异，切到「仅在线 TTS」再试听（明显的词：schedule、either、tomato、can't、dance）
- 播放前已调用 `wx.setInnerAudioOption({ obeyMuteSwitch: false })`，iPhone 静音键打开时也能出声
- 快速连点不叠音（递增令牌作废旧回调）；每次播放有 5~6 秒超时兜底
- 慢速/正常速是**两套独立文件**，切换语速会换文件，不是变速变调

### 常见问题排查

| 现象 | 排查顺序 |
|---|---|
| **全部无声** | ① 域名是否配全（见第二节第 4 步）② 云函数是否部署成功 ③ 设置页切「仅在线 TTS」验证在线通道是否通 ④ 点「试听发音」 |
| 部分句子无声 | 该条音频未成功生成/上传 → 跑一次全量差集核对；或切「自动」，会兜底到在线 |
| 音色不统一 | 说明该条降级到在线了。云端音频缺失或链接过期（重试会自动重签） |
| 按钮按了没反应 | 已修：播放中/按下都有状态反馈。若仍无，检查是否用了旧的 CSS `:active`（小程序里不可靠，须用 `hover-class`） |
| 长句挤成一行 | 已修：flex 子项需 `min-width:0`。若改样式时误删，会复发 |
| 日志报 `backgroundfetch privacy fail` | **误报，与本项目无关**（全项目未调用该接口；朗读链路用到的 `callFunction` / `createInnerAudioContext` / `downloadFile` 都不在隐私接口清单） |
| 设置页报「云函数 sync 还没部署」 | 开发者工具里右键 `cloudfunctions/sync` → 上传并部署；或命令行 `tcb fn deploy sync -e <环境ID>` |
| 设置页报「云端集合 progress 不存在」 | 云开发控制台 →「数据库」→ 新建集合 `progress`。云函数里也做了兜底（不存在自动建一次） |
| 另一台设备进度没变化 | ① 点「立即同步」看具体报错 ② 确认两台设备登录的是**同一个微信**——不同微信号 = 不同 openid = 两份完全独立的进度，这是设计如此，不是 bug |

## 五、与 H5 版的功能对照

| 功能 | H5 | 小程序 |
|---|---|---|
| 课程 / 打卡 / 重点词 | ✓（52 周 1300 词） | ✓（**78 周 8000 词**） |
| 语音朗读 | `SpeechSynthesis` + 在线 TTS 混合（**无法选发音人**，各设备声音不一致，部分设备无英文语音包） | **预生成高清音频**，固定音色、零延迟、离线可播，失败兜底在线 TTS |
| 间隔重复复习 | ✓ | ✓（1/2/4/7/14/30/60/120 天 + 到期页签） |
| 多端进度同步 | 无（localStorage 单机） | ✓ **云数据库自动同步**（openid 认人、无需登录）；另有「进度备份」导出 / 导入作为兜底 |
| 离线使用 | PWA 缓存（部分支持） | 播过的音频可离线；其余需网络 |
| 添加到桌面 | PWA（安卓可） | 微信内固定入口，更方便 |

## 六、注意事项
