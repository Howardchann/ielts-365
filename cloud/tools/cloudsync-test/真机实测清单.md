## 1. 三条前置（漏一条就会把正常现象误判成 bug）

### 1.1 手机上的代码必须是「这一版」⚠️ 最容易翻车

**第 0 步：上传 / 预览之前，先跑一次构建标识脚本**

```bash
node tools/stamp-build.js
# → ✅ 已写入 miniprogram/utils/build-info.js
#   sha=8dad358  branch=cloud-sync  dirty=false  builtAt=09-24 17:52
```

它把当前 `HEAD` 的短 sha 固化成常量，设置页「关于」那行会显示成
`版本V2.0 · 开发版 · 8dad358 · 09-24 17:52`。
**忘了跑不会报错，但界面上是上一次的 sha —— 会误导判断**（没有官方"上传前执行命令"的钩子，只能靠流程）。
`dirty=true` 时 sha 后会带 `*`，表示"这一版不是干净的提交"。

**第 1 步：选入口**

- 开发者工具点「**上传**」→ 只产生**一个新的开发版**，**不会自动更新体验版**
- 想走体验版：上传后到 mp 后台 →「版本管理」→ 开发版本列表 → 找到**最新那个** → 点「**选为体验版**」
- 想更快：直接用工具的「**预览**」扫码 —— 拿到的是**扫码那一刻工具里的代码**（= 最新开发版、= 磁盘当前分支），
  **不需要任何后台操作**，是回归首选

**判据：打开小程序 → 设置 → 关于，看那行字。**

| 看到什么 | 结论 |
|---|---|
| sha = 你刚跑的 `node tools/stamp-build.js` 输出的 sha | ✅ 手机上就是这一版 |
| sha 是旧的、或只有「版本V2.0」没有 sha | ❌ 手机上跑的还是旧版 —— 回来看这一步 |
| 环境显示「体验版」但 sha 对不上 | ❌ 后台的体验版没更新（最常见的翻车点） |
| 环境显示「开发版」 | 说明是「预览」或开发版工具进来的，代码 = 扫码那一刻的磁盘代码 |

> 这条以前**没法验**（程序里只有写死的 `版本V2.0`），真机数据也反推不出来 ——
> 正常路径新旧代码行为相同。加了构建标识后，以后一眼可辨。

### 1.2 两端必须是同一个微信号

`openid = f(appid, 微信号)`。手机与开发者工具必须登录**同一个微信号**，
否则云端是两份记录，「同步不通」是**正常**的、不是 bug。
手机上「我 → 头像」确认；工具右上角确认登录账号。

### 1.3 先导出备份

真机实测会**真的改动云端那条 `progress`**（那是你的真实进度）。
设置页 →「进度备份」→ 导出 → 存到「文件传输助手」。测岔了可以用**覆盖导入**还原。

## 2. 入口怎么选（差别在「要不要校验服务器域名」）

| 入口 | 代码版本 | 校验服务器域名 | 适合 |
|---|---|---|---|
| 工具内模拟器 | 磁盘当前分支 | ❌ 不校验 | 快速看功能 |
| **预览（扫码）** | 最新开发版 | ✅ 校验 | **真机回归首选**（最快、无需后台） |
| 真机调试（扫码） | 最新开发版 | ❌ 不校验 | 看 console / 排错 |
| **体验版** | 后台指定的那个开发版 | ✅ 校验 | **上线前最终验收** |
| 正式版 | 已发布 | ✅ 校验 | 上线后 |

> **音频这块的已知现状**（`AI-CONTEXT §2.2` 实测）：本项目用 `InnerAudioContext` 播云存储签名直链，
> **不受 downloadFile 合法域名限制 → 不配域名也能出声**。
> 但**要落本地缓存就必须配 downloadFile 域名**（云存储桶域名 + `dict.youdao.com` + `fanyi.baidu.com`）；
> 没配时**落盘会静默失败** —— 不影响播放，但**断网后听不到**（因为根本没缓存）。见 B3。

## 3. 用例清单

### A. 云同步回归（**本次必做**）

| # | 操作 | 期望 |
|---|---|---|
| A1 | 手机把小程序从「最近使用」划掉 → 重新打开 | 无报错弹窗；打卡数 / 收藏数与工具端一致（冷启动拉全量） |
| A2 | 手机打卡任一天 → **等约 3 秒**（防抖 2.5s）→ 工具端点「立即同步」 | 工具端出现该打卡 |
| A3 | 工具端收藏一个词 → 「立即同步」→ 手机切后台再切回前台 | 手机上看得到该收藏（切回前台会触发一次对齐） |
| A4 | 手机取消 A3 那个收藏 → 等 3 秒 → 工具端同步 | 工具端该词消失，**不会复活** |
| **A5** | 手机在复习页对某个词点「记得了」→ 等 3 秒 → 同步；工具端同步 | 工具端该词复习次数 +1 —— **本次改动就在这条路径上** |
| A6 | 手机设置页关掉同步开关 → 复习几个词 → 点同步 | 提示同步已关闭；**本机记录仍在**（关同步不影响本机） |
| A7 | 手机重新打开开关 → 同步 | 关闭期间攒下的记录一次补齐 |

> ⚠️ **A4 有个"测不出墓碑"的陷阱**：不能只"两端各点一次同步"——
> `buildPayload()` 每次推的是**全量 core**，两端推相同的最新状态时裁决器永远不会出错，**根本测不到墓碑**。
> 要真正验证，必须构造**一端持旧数据**：关掉一端的同步开关使其**冻结** → 另一端取消 → 再打开开关
> （`setSyncEnabled(true)` 内部会直接推全量）。构造方法与云端时序见 CHANGELOG 2026-09-23「六」。

## 4. 云端独立核对（可以让 AI 代做）

在手机上操作完**说一声**，可以直接查云端 `progress` 印证，不用靠肉眼判断：

- `checkedDays` / `starredWords` 有没有新值、**时间戳**是不是刚才
- `updatedAt`、`reviewRev` 有没有按预期变化
- 复习记录（`kind:'rs'` 分片）里该词的 `correct` 次数

**哪些用例云端查得到（其余只能靠现场观察）**：

| 用例 | 云端痕迹 | 判据 |
|---|---|---|
| A2 打卡 | ✅ | `checkedDays.<天>` 时间戳 = 刚才 |
| A4 取消收藏 | ✅ | `unstarredWords.<词>` 出现墓碑；`starredWords` 里无该词 |
| A5 复习 | ✅ | `#rs<i>` 分片里该词 `correct` +1、`lastReviewedAt` = 刚才；`reviewRev` +1 |
| A3 工具端收藏→手机可见 | 🟡 间接 | 若随后在手机上取消了它，墓碑出现即说明手机收到过（`store.js` 只在词确实在列表里时才写墓碑） |
| A1 / A6 / A7 | ❌ 无 | 纯本地行为或"不上送"行为，云端看不出来 —— **现场看提示文案与界面** |
| B 音频 / C 剪切板 / D 边界 | ❌ 无 | 真机专属，必须现场判断 |

> ⚠️ **另一个查不出来的**：手机跑的是哪一版客户端代码。正常"复习 → 同步"路径新旧版本行为完全相同，
> 云端数据分辨不出来。
> **所以要先按 §1.1 确认入口**（用「预览」最稳），**并直接看设置页「关于」那行的构建标识** ——
> 那是脱离云端、最直接的一条判据。

## 6. 一眼分辨「这是不是 bug」

| 现象 | 结论 |
|---|---|
| 云端文档里 `checkedDays.w1d1` 与 `uncheckedDays.w1d1` **同时存在** | ❌ 不是 bug。云开发 `update` 对对象字段是**合并**语义、旧的键删不掉；正确性由**读取侧取更晚者**保证 |
| 同步成功，但云端 `updatedAt` 没变 | ❌ 不是 bug。值没变化就不写库（**这正是本次修复的用意**） |
| 微信里搜不到「开溜」 | ❌ 不是 bug。体验版搜不到，只有正式版才进搜一搜 |
| 断网时听不到音频 | ❌ 不是 bug。downloadFile 域名未配 → 落盘静默失败，无缓存 |
| 换个微信号登录，同步不通 | ❌ 不是 bug。记录按 **openid** 隔离，换微信号 = 另一份数据 |
| 首次进小程序，云同步报错一次后自动好了 | 大概率是**集合首次自动创建**的重试（见测试台【1】）；若每次都报，才是 bug |
