# 备份导入导出测试清单

> 备份是**手动快照**，与云同步相互独立：导出成一段 JSON 文本自己保存，导入时按时间戳合并或整体覆盖。
> 本清单每条期望值均从 `miniprogram/utils/store.js`（`exportBackup` / `importBackup`，L408-552）与
> `pages/settings/settings.js`（`doImport`）的实际行为推出，不是想当然。

## 0. 机制速览（判读期望值全从这里来）

| 机制 | 行为 | 代码位置 |
|---|---|---|
| 导出 | 「导出备份」→ 生成 JSON + **自动复制到剪贴板**。格式 `{app:'ielts-365', v:3, exportedAt, data:{起始日/打卡/取消打卡/收藏/取消收藏/复习记录/语速/口音/引擎}}` | store.js L411-422 |
| 合并导入 | 打卡/收藏按**时间戳**合并（取消的墓碑能压过更早的收藏）；复习记录**按词取 lastReviewedAt 较新者**——快照语义，**不累加次数** | L525-534, L499-508 |
| 覆盖导入 | 打卡/取消打卡/收藏/取消收藏/复习记录**五类整体替换**；起始日/语速/口音/引擎仅当备份有值时应用，settingsAt 取较新 | L517-524, L536-540 |
| ⚠️ 云端传导 | 导入后，备份里的复习记录**全部标记待推**，下次同步推上云端 → **覆盖导入 + 同步 = 云端也回滚到备份时点** | L542-543 |
| 幂等 | 重复导入同一份备份：新增 0 天 0 词，复习次数不累加（快照，不是增量日志） | L498 注释 + L505 `it >= lt` |
| 非法输入 | 空内容→toast「请先粘贴备份内容」；坏 JSON→「解析失败…」；`app` 字段不是 `ielts-365`→「这不是「开溜」的备份」 | L511-513, L474-475 |

## 1. 前置（三条，漏了会污染真实进度）

1. 🔴 **先做保险备份**：设置 →「导出备份」→ 粘贴到备忘录保存，命名为「真实进度-0925」。
   后面所有测试都会改动真实数据，收尾全靠它救回（T6）。
2. **记下起点数字**：当前打卡天数 / 收藏词数 / 复习记录词数（弹窗里的"合并后共 X 天"要对着它判读）。
3. **环境**：开发者工具模拟器即可（备份不走网络域名）；但导入会写**云端真实数据**（见机制表 ⚠️ 行），测完必须做 T6。

## 2. 用例

### T1 导出基本功能

| 步骤 | 期望 |
|---|---|
| 设置 →「导出备份」 | 弹出备份文本 + toast「已复制」 |
| 粘贴到备忘录检查 | 是完整 JSON；含 `"app":"ielts-365"`、`"v":3`、`"exportedAt"`（时间为刚导出的时刻）；`data.checkedDays` 里有你打过的卡（如 `w1d1`/`w1d2`） |
| 点「导出备份」旁边的文本区手动「复制」按钮（若有） | toast「已复制」；再粘贴内容一致 |

### T2 覆盖恢复（replace）

先制造差异（这些是"备份之后才发生"的改动）：
打卡一个新日子、收藏一个新词（记为 **X**）、到「到期复习」对任意词点一次「记得了」。

| 步骤 | 期望 |
|---|---|
| 「导入恢复」→ 粘贴 T1 的备份 → 点「**覆盖导入**」 | modal「覆盖完成 / 已替换为备份中的 N 天打卡、M 个重点词、K 个复习记录」 |
| 回页面核对 | 新打卡消失、词 X 消失、复习记录回到备份时点 |
| 「关于」/设置项 | 起始日、语速、口音回到备份值 |
| 等自动同步（约 3 秒）后查云端 | **云端也被带回备份时点**（reviewRev 回退、新增复习词消失）——这是设计行为不是 bug；T6 会救回 |

### T3 合并导入（merge，双向差异）

制造**双向**差异：本地打卡一个新日子 A、收藏一个新词 **Y**（备份里都没有）；
而备份里有词 **X**（T2 之后本地已没有它）。

| 步骤 | 期望 |
|---|---|
| 粘贴同一份备份 → 点「**合并导入**」 | modal「合并完成 / 新增 N 天打卡、M 个重点词 / 合并后共 X 天、Y 个重点词 / 已恢复 K 个复习记录」 |
| 核对 | 备份里的打卡并进来、词 X 回来；**同时**本地的日子 A 和词 Y 都还在（双向保留） |
| 复习记录 | 本地与备份按词取较新者；两边都有的词次数不翻倍 |

### T4 重复导入（幂等性）

| 步骤 | 期望 |
|---|---|
| 紧接着把**同一份备份**再「合并导入」一次 | modal「新增 **0** 天打卡、**0** 个重点词」；"合并后共"数字与上次一致 |
| 挑一个两边都有的复习词核对 correct 次数 | **不累加**（仍是原值）——快照语义 |

### T5 非法输入（三个错误分支）

| 输入 | 期望 |
|---|---|
| 什么都不粘，直接点导入 | toast「请先粘贴备份内容」 |
| 粘贴半截 JSON（复制时漏掉后半段） | modal「导入失败 / 解析失败：不是完整的备份文本，请重新复制一次」 |
| 把备份里 `"app":"ielts-365"` 改成别的值再导入 | modal「导入失败 / 这不是「开溜」的备份」 |

### T6 收尾：恢复真实进度（必做）

| 步骤 | 期望 |
|---|---|
| 「导入恢复」→ 粘贴**保险备份** → 「覆盖导入」 | 统计回到前置第 2 步记下的起点数字 |
| 等同步完成（约 3 秒） | 云端随之回到真实进度 |
| 说一声 → AI 查云端 `progress` 核对 | `updatedAt` 是刚才、`reviewRev` 比测试前 +N（N=导入恢复的复习词数）、收藏/打卡与起点一致 |

## 3. 常见误判

| 现象 | 定性 |
|---|---|
| 覆盖导入后云端数据也"回退"了 | **正常**——导入的复习记录会推云（机制表 ⚠️ 行），不是同步 bug |
| 合并导入显示"新增 0 天 0 词" | 若备份与本地一致，0 就是正确结果；判读看"合并后共 X 天"的总数 |
| 重复导入后复习次数没翻倍 | **正常**——快照语义，正是防重复累加的设计 |
| 覆盖导入后语速/口音没变 | 备份里该字段缺失或超范围（0.5-2 之外）时不会应用；检查备份 JSON 的 `data.rate` |

## 4. 云端独立核对

手机/模拟器上操作完说一声，可以直接查云端 `progress` 印证（AI 代查）：`updatedAt`、`reviewRev`、
`checkedDays` / `starredWords` / `unstarredWords` 时间戳、`#rs*` 分片词表。

## T7 清除学习记录（从0开始）—— 2026-09-25 新增（f0e845a 之后）

> 位置：设置 → 备份与重置 → 清除学习记录（红色按钮，二次确认）。
> 机制：云函数只有 merge（只增不删），所以重置 = 打卡/收藏写"取消"墓碑、复习写零记录，
> 用既有时间戳规则把云端压下去；其他设备下次同步自动收敛到空。startDate 回到下一个周一（进准备期）。

| 步骤 | 期望 |
| --- | --- |
| 点「清除学习记录」→ 确认弹窗 | 文案包含"云端一并清除、其他设备同样清空、不可撤销、建议先导出备份" |
| 点取消 | 什么都不发生 |
| 先「导出备份」→ 再清除 | 导出的备份文本仍是清除前的完整进度（可用来反悔恢复） |
| 确认清除 | 设置页：已完成 0 天 · 收藏 0 · 复习记录 0；「今日」页回到准备期（下一个周一开学） |
| 等同步完成 | 云端打卡/收藏/复习全部被压平（AI 代查：`#rs*` 分片里 correct+wrong 全为 0；core 的 checkedDays 全部被 uncheckedDays 压住） |
| 复习页 | 随机抽查提示"从已学词汇中随机抽查"（池为空）；到期词 0 |
| 重新打卡 Day 1 → 同步 | 正常生效（旧墓碑被更晚时间戳自然压过），其他设备同步后一致 |
| （可选）导入 T7 前导出的备份（覆盖） | 进度完整恢复并推云——重置可被备份"反悔" |
